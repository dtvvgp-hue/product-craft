# UI/UX and visual quality

Start with the job-to-be-done, primary action, content priority, and failure modes. Define the page or screen structure before styling. Use a small token set for color, type, spacing, radius, elevation, and motion so the interface feels like one system.

## Required pass

- Check desktop, tablet, and narrow mobile layouts.
- Check keyboard navigation, visible focus, labels, contrast, reduced motion, and semantic landmarks.
- Design loading, empty, error, disabled, success, and permission states.
- Use motion to explain state changes or hierarchy. Keep it interruptible, fast, and respectful of reduced-motion preferences.
- Use real copy and realistic content lengths. Do not hide weak UX behind placeholder text.
- Prefer one strong visual idea over a pile of effects.

## Anti-slop review

Remove generic hero copy, arbitrary gradients, repeated card grids, needless pills, fake dashboard numbers, inconsistent radii, decorative animation with no meaning, and any component that looks copied from a template without serving the product.

For redesigns, preserve the existing information architecture unless evidence shows it is the problem. Improve the highest-friction path first, then consolidate tokens and components so the improvement survives future changes.
