# Shipping and release

Before release, verify the intended build artifact, environment variables, migrations, routes, analytics, error reporting, accessibility smoke path, and rollback option. Distinguish local validation from staging and production validation.

Use a release checklist proportional to risk. For risky changes, ship behind a flag or in a small slice when the platform supports it. Capture the exact command or workflow used and the resulting evidence. After release, check the critical path and record follow-up work instead of quietly carrying uncertainty.
